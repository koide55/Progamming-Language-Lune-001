# Lune フォーマッタ仕様 (`lune fmt`)

Version: 0.1 draft
Related: `LEXER_PARSER_SPEC.md`, `SYNTAX_SPEC.md`, `LANGUAGE_SPEC.md`

`lune fmt` は Lune ソースを正準スタイルへ整形する。実装は `lune/formatter.py`。

## 1. 目的と保証

- **正準性**: 出力はソースの元の空白・改行に依存せず、AST から一意に決まる。
- **冪等性**: `fmt(fmt(x)) == fmt(x)`。
- **意味保存**: 整形後のソースを再パースし、AST が（span を除いて）元と一致することを検査する。一致しなければ整形を中止しエラーにする（コードを壊さない安全網）。空文のみの `BlockExpr` はその結果式と等価とみなす（インライン body と次行 body の差を吸収する）。
- **データ非損失**: `#` 行コメントは保持する。`###` ブロックコメントを含むファイルは、取りこぼしを避けるため整形せずエラーにする（将来対応）。

## 2. 方式

パースして AST を得て、AST をプリティプリントして正準ソースを生成する（トークン列の書き換えではない）。コメントは別途 `scan_comments` で位置つきに収集し、文・宣言境界で差し込む。

## 3. スタイル規則

- インデントは 4 スペース。タブは使わない。
- トップレベル宣言・ブロック文の間の空行は、元ソースに空行があった箇所にのみ 1 行入れる（連続空行は 1 行に圧縮）。グルーピングは尊重するが増やさない。
- `let x = <式>` は 1 行。値がブロック的（`match` / `if` ブロック形 / `while` / `for` / 文列ブロック / `IO:` / ブロック body の `lazy`）なら `let x =` の次行にインデントして本体を置く。
- `def f[T](params): Ret =` の次行にインデントして本体を置く（単純な式本体でも次行）。
- `record`/`type` はヘッダ行の次にフィールド／コンストラクタをインデントして並べる。
- 演算子は前後 1 スペース。優先順位に基づき必要な括弧のみを付け、冗長な括弧は落とす。
- 関数呼び出し・タプルはインラインで描画する。
- **リストリテラル**はインラインが 88 桁を超える場合、1 要素 1 行（末尾カンマ付き）に折り返す。それ以外はインライン。
- コメント: 構文要素の直前の行頭コメントはその要素の前に、同一行の行末コメントはその要素の先頭行の末尾に付す（前に 2 スペース）。配置できないコメントは近傍の行頭コメントとして出力し、失わない。

## 4. CLI

```sh
lune fmt <file>            # 整形結果を stdout に出力（ファイルは 1 つ）
lune fmt --write <file>... # ファイルをその場で書き換える（変更時のみ）
lune fmt --check <file>... # 未整形なら `would reformat` を表示し終了コード 1（CI 向け）
```

`--write` と `--check` は排他。既定（stdout）はファイル 1 つのみ。パースエラーや未対応構文（`###`）は該当ファイルをスキップして終了コード 1。

## 5. v0.1 での制限

- `###` ブロックコメントは未対応（該当ファイルは整形しない）。
- 折り返しはリストリテラルのみ。長い呼び出し引数はインラインのまま。
- コメントの列揃え（複数スペースでの整列）は保持しない。
- 行末コメントは構文要素の「先頭行」に付く（複数行構文の途中行への行末コメントは先頭行へ寄せる場合がある）。
